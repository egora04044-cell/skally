# Снимок диалога — деплой VPS (Scally)

Фиксация на момент паузы по просьбе сохранить переписку и остановить локалку.

## Локальный сервер разработки

Остановлен процесс, слушавший **порт 3000** (типичный `next dev`). Чтобы снова поднять сайт локально: из каталога проекта `npm run dev`.

## Что обсуждалось по проекту Scally

- Ранее добавлялись безопасность (заголовки, редирект билетов `/go/tickets/[ref]`, и т.д.), потом с главной убрали поясняющий абзац про партнёрского оператора билетов и редиректы.
- Отдельный проект с Phantom: папка **`D:\my-token-site`** (дефисы), инструкции **DEPLOY.md** / **DOMAIN.md** на диске там.
- Для **Scally** добавлен деплой под VPS (как у токен-сайта), файлы в репозитории:
  - `ecosystem.config.cjs` — PM2, имя процесса `scally`, порт `3000`
  - `deploy.sh` — `npm ci`, `npm run build`, перезапуск PM2
  - `nginx.conf.example` — прокси на `127.0.0.1:3000` (подставить свой домен)
  - `DEPLOY-VPS.md` — полная инструкция по шагам

## Пошаговый план (с чего продолжить)

Общий порядок кратко: VPS + DNS → Node 20 + PM2 → код в `/var/www/scally` → `.env.production` (`NEXT_PUBLIC_SITE_URL=...`) → `./deploy.sh` → Nginx → Certbot → дальше `git pull` + `./deploy.sh`.

**На паузе на шаге 1 подготовки:**

1. VPS (Ubuntu/Debian), IP, порты 22 / 80 / 443  
2. Домен: A `@` и при необходимости A `www` → IP VPS  
3. Убедиться, что заходит **SSH**: `ssh user@IP`

После этого следующий блок из чата должен быть **шаг 2: установка Node.js и PM2 на сервере**.
