# Безопасность и эксплуатация

Кратко: что уже в коде/конфиге и что остаётся на стороне хостинга, партнёров и процессов.

## Уже учтено в репозитории

| Тема | Реализация |
|------|------------|
| Редирект на билетного оператора | Только `/go/tickets/[ref]`; URL из `ticket-destinations.ts`; HTTPS и whitelist hostname (`TICKET_ALLOWED_HOSTS`). |
| Security headers | `next.config.ts`: CSP (строже в prod), nosniff, Referrer-Policy, XFO DENY, Permissions-Policy, COOP; HSTS только в prod. |
| www / apex | Опционально `CANONICAL_SITE_HOST` + `src/middleware.ts` (только prod). В Next.js 16 возможно предупреждение о смене соглашения `middleware` → `proxy` — следите за релиз-нотами и при необходимости перенесите редирект. |
| XSS в JSON-LD | `src/lib/jsonld.ts` экранирует `<` для `application/ld+json`. |
| Секреты | `.gitignore`: `.env*`, исключение `!.env.example`. Никаких сессионных секретов в коде под этот статичный сайт. |
| Внешние ссылки | `rel="noopener noreferrer"` на транзишен-сайт билетов и уже был на соцсетях. |
| Комплайенс-UX | Юр. страницы; уведомление о cookie; формулировки про оператора билетов в оферте. |

## Зона ответственности платформы (Vercel, Cloudflare, Reg.ru и т.д.)

1. **HTTPS** на канонических доменах, автообновление сертификата (Let’s Encrypt / Cloudflare Universal SSL / аналоги).
2. **301 на один канонический домен** — часто задаётся в панели хостинга; дублируется нашим middleware при наличии `CANONICAL_SITE_HOST`.
3. **HSTS + preload**: заголовок отдаём из Next в prod; заявку в preload-лист браузера и длинную политику согласуют отдельно.
4. **CDN / WAF / bot / DDoS** — включаются у CDN.
5. **Мониторинг** (Sentry, логи 4xx/5xx, алерты), **2FA** на GitHub/хостинг/регистратор DNS.

## Билеты и контент

- Перед добавлением реального URL билетов добавьте **hostname оператора в** `src/content/ticket-destinations.ts` → `TICKET_ALLOWED_HOSTS`, затем пару **`ref → https://...`** и выставьте тот же `ticketRef` у концерта в `src/content/site.ts`.
- Не вводите «открытый редирект» по query-параметру.

## Формы, API, антибот, rate limit

Публичных форм и API в этом проекте нет. При добавлении — серверная валидация, лимиты (edge/KV/upstream), CAPTCHA/Honeypot по модели угроз.

## Зависимости

- Периодически: `npm audit`. Текущие предупреждения по дереву зависимостей `next` закрываются обновлениями фреймворка, когда выйдут исправления; не используйте `npm audit fix --force`, если оно предлагает откат major-версий.
- Авто-PR зависимостей: `.github/dependabot.yml`.

## Incident playbook (черновик)

1. Остановить/откатить деплой при критической уязвимости.  
2. Ротировать скомпрометированные секреты.  
3. Проверить логи CDN и приложения по временному окну инцидента.  
4. Зафиксировать постмортем и задачи на исправление.
